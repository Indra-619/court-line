## Temuan per dimensi

### D1 Architecture — 8/10

Utuh: main.go composition root, handlers hanya pegang interface repository,
infrastructure mengimplementasi, models BSON terpisah dari entity domain.

Gap:
- A1 (minor) `internal/database/mongo.go` masih ada (Connect + global Client) tapi
  tidak dipakai main.go — dead code yang membingungkan; hapus atau jadikan constructor.
- A2 (minor) Package-level mutable state tersisa: `tokenBlacklist`, `userRoleLookup`
  (middleware, di-set via SetXxx saat startup) dan `exchangeStore` (handlers).
  Bisa di-inject ke struct supaya benar-benar bebas global dan lebih mudah di-test paralel.
- A3 (minor) `pkg/result.Result[T]` dibuat tapi tidak dipakai handler mana pun — dead code.
- A4 (design) Exchange code store in-memory: tidak survive restart dan tidak bisa
  multi-instance. Sudah didokumentasikan sebagai trade-off; kalau mau scale-out,
  pindahkan ke Mongo/Redis dengan TTL.
- A5 (design) Check-then-insert double-booking punya race window (didokumentasikan).
  Solusi benar: unique index komposit {courtId, date, slot} atau transaksi replica-set.

### D2 Code Quality — 8/10

Bagus: sentinel errors (ErrNotFound/ErrInvalidID), parseHexID terpusat, validasi
strict (round-trip date, zero-padded clock), pricing menit-exact tanpa rounding,
komentar menjelaskan trade-off.

Gap:
- Q1 (minor) Duplikasi konstanta BookingStatus di `models` dan `entity` (dua enum
  identik). Rawan drift; satu sumber + alias lebih aman.
- Q2 (minor) `booking_handler.go` CreateBooking: `now := time.Now()` padahal ada
  `nowFn` injectable di file yang sama — inkonsisten, menyulitkan test waktu.
- Q3 (minor) Error binding Gin (`err.Error()`) dibocorkan mentah ke client di
  beberapa handler — bisa membocorkan nama field internal; petakan ke pesan ramah.
- Q4 (minor) `UpdateCourt` tidak meng-update `IsAvailable` (field hilang dari
  $set) — admin tidak bisa menonaktifkan court lewat API. Lihat juga P1.
- Q5 (nit) Frontend: `pages/index.vue` fallback ke sample data hardcoded saat API
  gagal — demo data bisa muncul di production dan menutupi outage. Ganti empty/error state.

### D3 Security — 6/10

Kuat (terverifikasi di kode + test): OAuth state random + constant-time compare,
one-time exchange code 5 menit, JWT HMAC-only + jti blacklist fail-closed,
refresh token hash-only + single-use rotation, logout revoke semua sesi,
PII redaction di endpoint publik, CORS allowlist eksplisit, fail-fast JWT_SECRET,
non-root containers, Mongo tanpa port published, redirect same-origin only.
Tidak ada v-html/innerHTML/eval di frontend.

Gap:
- S1 (MAJOR) 12 vulnerability Go REACHABLE (govulncheck): 11 di stdlib
  (net/http, http2, crypto/tls, crypto/x509, net/textproto — GO-2026-6603..6859)
  + 1 di github.com/klauspost/compress@v1.17.6 (GO-2026-6865, fix v1.20.2).
  Fix: build dengan Go >= 1.27.4 (Dockerfile sekarang golang:1.26-alpine —
  lebih tua dari go.mod go 1.26.0 dan stdlib yang kena vuln) + bump klauspost/compress.
- S2 (MAJOR) Tidak ada rate limiting di endpoint auth (login/exchange/refresh)
  maupun booking. Brute-force exchange code 32-byte memang tidak praktis, tapi
  DoS endpoint + spam booking terbuka. Tambah gin rate limiter per-IP.
- S3 (moderate) `scripts/seed_admin.sh` interpolasi `$EMAIL` langsung ke string
  mongosh --eval → script injection kalau argumen mengandung quote. Pakai
  parameter binding atau validasi format email dulu.
- S4 (moderate) JWT access token 24h — panjang untuk access token; praktik umum
  15 menit + refresh. Refresh rotation sudah ada, jadi memperpendek murah.
- S5 (moderate) Tidak ada security headers (HSTS, X-Content-Type-Options,
  X-Frame-Options/CSP) di backend maupun Nuxt config.
- S6 (minor) `OptionalAuthMiddleware` tidak cek jti blacklist — token yang sudah
  di-logout tetap dikenali sebagai user di endpoint optional-auth. Saat ini tidak
  ada route yang memakainya, tapi middleware siap dipakai = jebakan laten.
- S7 (minor) Tidak ada audit log untuk aksi admin (create/update/delete court).
- S8 (minor) Cookie oauth_state: Secure di-set dari env COOKIE_SECURE (default
  false) — pastikan production set true; HttpOnly + SameSite=Lax sudah benar.

### D8 Performance — 6/10

- P1 (moderate) Semua list endpoint tanpa pagination/limit: GET /api/courts,
  GET /api/bookings, GET /api/courts/:id/bookings (FindAll/FindByUserID/FindByCourtID
  tanpa Limit). Data bertumbuh → response membengkak. Tambah limit+offset atau
  cursor, default cap (mis. 100).
- P2 (moderate) AuthMiddleware hit Mongo (blacklist Exists) SETIAP request
  authenticated. Bisa cache in-memory TTL pendek (mis. 30 detik) dengan
  invalidation saat logout, atau terima trade-off dan dokumentasikan.
- P3 (minor) FindActiveByCourtAndDate mengambil seluruh booking aktif lalu
  overlap-check di app. Index komposit {courtId, date, status} sudah ada —
  cukup baik untuk skala kecil; bisa dipindah ke query range kalau perlu.
- P4 (minor) Frontend fetch courts tanpa cache/stale handling; setiap mount
  refetch. Nuxt useFetch/useAsyncData dengan getCachedData lebih idiomatic.
- P5 (design) Booking tidak cek `court.IsAvailable` — court yang di-disable
  admin tetap bisa dibooking (ini juga correctness bug, lihat Q4).

## Roadmap pengembangan fitur (di luar remediasi)

Fungsi inti (browse court, booking, auth, admin CRUD) sudah lengkap dan teruji.
Yang belum ada dan layak dikembangkan, urut nilai/usaha:

1. Booking lifecycle: user bisa cancel booking sendiri (status cancelled sudah
   ada di enum tapi tidak ada endpoint/UI-nya), admin confirm/complete.
   Ini gap fungsional paling nyata — booking pending tidak bisa diapa-apakan.
2. Availability calendar per court per tanggal di frontend (data endpoint
   publik sudah ada, tinggal visualisasi slot terisi vs kosong).
3. Payment integration (Midtrans/Xendit) — enum status belum punya `paid`;
   tambah state paid + webhook handler. Login page sudah menjanjikan
   "Secure payment" tapi belum ada implementasi.
4. Admin dashboard: list semua booking, kelola user, toggle IsAvailable court.
5. Notifikasi email/WhatsApp (konfirmasi booking, reminder H-1).
6. Multi-venue: saat ini satu lokasi implicit; tambah entity Venue kalau
   mau jadi marketplace sungguhan.
7. Observability: structured logging (slog), request ID, metrics Prometheus,
   error tracking — sekarang hanya log.Printf standar.
8. OpenAPI spec + generated client untuk frontend (menghapus fetch manual
   berulang di pages).
